# Engineering Principles

Nunca comenzar implementando.

Siempre seguir este orden:

1. Comprender el negocio.
2. Definir el MVP.
3. Diseñar la arquitectura.
4. Diseñar el modelo de datos.
5. Dividir en tareas pequeñas.
6. Implementar.
7. Revisar.
8. Testear.

# Language / Idioma de desarrollo

Este proyecto se desarrolla en **español**. Convenciones:

- **Código**: comentarios, nombres de variables/funciones, identificadores y mensajes en español, usando español neutral/profesional (sin voseo, sin slang).
- **UI**: todos los textos de interfaz, mensajes de error y de éxito en español.
- **Commits**: mensajes de commit en español, con conventional commits (ej. `feat(auth): agregar registro de usuarios`).
- **Documentación**: docs, specs y README en español.
- **Excepciones**: términos técnicos establecidos (API Routes, ORM, middleware, endpoint) y nombres de paquetes/librerías se mantienen en inglés.
- **Código generado por herramientas**: se traduce al español si es texto visible (UI, comentarios, mensajes); nombres internos de la herramienta se respetan.

Esta convención de proyecto anula el default de inglés de los agentes para este repositorio.
